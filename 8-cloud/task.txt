I’ll simplify the Task Manager app to make it even easier for beginners, focusing on the absolute basics using Salesforce’s point-and-click tools. The simplified app will:
- Track tasks with just **Task Name** (text) and **Status** (picklist) fields.
- Include a custom object and a tab.
- Skip automation, custom home pages, and advanced security for now.
- Be built in a Salesforce Developer Edition org.

This version minimizes steps while still creating a functional app. Below is a step-by-step guide.

### Simplified Step-by-Step Guide to Build a Task Manager App in Salesforce

#### Step 1: Set Up Your Salesforce Environment
1. **Get a Salesforce Account**:
   - If you don’t have one, sign up for a free **Salesforce Developer Edition** at [developer.salesforce.com](https://developer.salesforce.com/signup).
   - Log in to your Salesforce org.
2. **Access Setup**:
   - Click the **Gear Icon** in the top-right corner and select **Setup**.

---

#### Step 2: Create a Custom Object for Tasks
A custom object will store task data.

1. **Go to Object Manager**:
   - In Setup, search for **Object Manager** in the Quick Find box and click it.
2. **Create a Custom Object**:
   - Click **Create** > **Custom Object**.
   - Fill in:
     - **Label**: Task
     - **Plural Label**: Tasks
     - **Object Name**: Task (auto-filled)
     - **Description**: A simple object to track tasks.
     - Check **Launch New Custom Tab Wizard after saving**.
   - Click **Save**.
3. **Add Custom Fields**:
   - After saving, you’re on the Task object’s details page. Under **Fields & Relationships**, click **New** to add:

Step-by-Step: Creating Custom Fields Using the Interface in the Screenshot
You’re currently in the New Custom Field wizard, at Step 1: Choose the Field Type. Let’s create the fields for your Task Manager app.

1. Create the "Task Name" Field (Text)
This field will store the name of the task as a text value.

Step 1: Choose the Field Type (Current Screen):
In the screenshot, under Data Type, you see options like "Auto Number," "Formula," "Roll-Up Summary," etc.
Scroll down (if needed) to find Text.
Select the radio button next to Text.
Click the Next button on the top right (as shown in the screenshot).
Step 2: Enter the Details:
Label: Enter Task Name (this is the display name for the field).
Length: Set to 80 (this defines the maximum number of characters allowed).
Required: Check the box to make this field mandatory (so users must enter a task name).
Leave other fields (like "Description" or "Default Value") blank for simplicity.
Click Next.
Step 3: Establish Field-Level Security:
Choose which profiles can see or edit this field. For simplicity, select Visible for all profiles (e.g., System Administrator).
Click Next.
Step 4: Add to Page Layouts:
Choose where this field appears on the Task object’s page layout. For now, accept the default (it will be added to the layout automatically).
Click Save.
You’ve now created the Task Name field! You’ll return to the Task object’s Fields & Relationships page.

2. Create the "Status" Field (Picklist)
This field will let users select the task’s status (Not Started or Completed) from a dropdown.

Start Again from Fields & Relationships:
On the Task object’s details page, under Fields & Relationships, click New to create another field. You’ll be back at the screen in the screenshot.
Step 1: Choose the Field Type:
In the Data Type list, scroll to find Picklist.
Select the radio button next to Picklist.
Click Next.
Step 2: Enter the Details:
Label: Enter Status.
Values: Choose Enter values, with each value separated by a new line.
In the text box, enter:
text
Not Started
Completed

Default Value: Select Not Started from the dropdown (so new tasks default to this status).
Leave other options (like "Sort values alphabetically") unchecked for simplicity.
Click Next.
Step 3: Establish Field-Level Security:
Again, make the field Visible for all profiles (e.g., System Administrator).
Click Next.
Step 4: Add to Page Layouts:
Accept the default to add the field to the page layout.
Click Save.

#### Step 3: Create a Custom Tab
A tab lets users access the Task object.

1. **Continue from Object Creation** (tab wizard opens automatically部分

   - **Tab Style**: Choose an icon (e.g., Checklist).
   - **Label**: Tasks
   - Click **Next**, **Next** (accept default profiles), then **Save**.

---

#### Step 4: Create the Custom App
Group the Task object into a simple app.

1. **Go to App Manager**:
   - In Setup, search for **App Manager** in Quick Find and click it.
2. **Create a New Lightning App**:
   - Click **New Lightning App**.
   - Fill in:
     - **App Name**: Task Manager
     - **Description**: A basic app to manage tasks.
     - **Logo**: Use default.
     - Click **Next**.
   - **Navigation**:
     - Add **Tasks** to **Selected Items**.
     - Click **Next**.
   - **Profiles**:
     - Select **System Administrator** profile.
     - Click **Save & Finish**.

---

#### Step 5: Test the Application
1. **Access the App**:
   - Click the **App Launcher** (waffle icon) in the top-left corner.
   - Search for **Task Manager** and select it.
2. **Create a Task**:
   - Click the **Tasks** tab > **New**.
   - Enter details (e.g., Task Name: "Send Email", Status: Not Started).
   - Click **Save**.
3. **View Tasks**:
   - In the Tasks tab, ensure your task appears in the list view.

1. Q: What is Salesforce?
A: Salesforce is a cloud-based Customer Relationship Management (CRM) platform that helps businesses manage sales, customer service, marketing, and custom applications.

2. Q: What is a Custom Object in Salesforce?
A: A Custom Object is like a table in a database that you create to store data specific to your app. In this practical, the “Comment” object is a custom object to store user comments.

3. Q: Why do we create custom tabs in Salesforce?
A: Custom tabs allow users to easily access the custom object data (like Comment records) from the Salesforce interface, just like clicking a tab in a web application.

4. Q: What is the purpose of creating a Lightning App?
A: A Lightning App combines various objects (standard and custom) into one interface, making it easier to access related data. It's like packaging everything into one convenient workspace.

5. Q: Why do we assign the app to a profile like System Administrator?
A: Profiles control what users can see and do. Assigning the app to the System Administrator profile ensures that users with that role have access to all the features of the app.

6. Q: What is the use of the “Allow Reports” checkbox when creating an object?
A: It enables users to generate reports based on the data from that object, which is useful for analysis and decision-making.

7. Q: How do you simulate the Salesforce app on mobile without using a physical phone?
A: We use Google Chrome Developer Tools, enable mobile device view (Toggle Device Toolbar), and access Salesforce as if it's on a phone. This helps test the mobile-friendliness of the app.

8. Q: What is the App Launcher used for?
A: The App Launcher is like a menu where you can find and open any app you’ve created or have access to within Salesforce.

9. Q: What are standard vs custom objects?
A: Standard objects (like Contacts, Accounts) are provided by Salesforce by default. Custom objects (like Comment) are created by the user for specific needs.
